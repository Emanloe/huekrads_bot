# HUEKRADS

Telegram-бот для групповых чатов с гномами, дуэлями, боссами, предметами, хуекрабами и случайными событиями. В Mini App можно посмотреть своего гнома, сменить экипировку и участвовать в боях. Игровые данные хранятся в SQLite.

## Гномы и дуэли

`/duel` регистрирует гнома в текущем чате и предлагает выбрать соперника. Для прямого вызова используется `/duel @username`. Соперник должен быть зарегистрирован в этом чате. Кнопки выбора соперника доступны только автору команды. `/me` тоже создаёт профиль, если его ещё нет.

Новый гном получает 20 очков. Победа добавляет 10, поражение отнимает 5, результат ограничен диапазоном от 0 до 100. Ноль очков сам по себе не запрещает драться. После кражи хуя гном не допускается к дуэлям до восстановления. При следующем игровом обращении в новый московский день очки возвращаются к 20, дневные победы обнуляются, потерянный хуй восстанавливается. Это происходит при обращении к профилю, а не отдельным заданием в полночь.

В чате может идти одна обычная дуэль. Первый атакующий выбирается случайно. Он указывает зону удара: голову, торс или пах. Защищающийся выбирает одну из тех же зон для блока. На выбор отводится 10 секунд; при таймауте зона выбирается случайно. Совпадение зон даёт блок, иначе удар попадает. После блока, промаха или поглощённого бронёй удара бойцы меняются ролями. Первое непоглощённое попадание завершает бой.

Перед проверкой зон есть 1% вероятности самоубийства атакующего. Если оно не выпало, отдельно проверяется промах с вероятностью 5%. Оружие и броня в сообщениях берутся из экипированных слотов; при пустом слоте текст использует нож и промасленную жилетку. Эти базовые названия не дают дополнительной защиты.

При поражении можно потерять хуй. В текущем расчёте шанс равен 20% плюс один процентный пункт за каждую дневную победу **проигравшего**, максимум 100%. Если у проигравшего было ноль очков в снимке на начало боя, кража срабатывает без броска. При краже есть отдельный шанс 5% передать победителю один случайный коллекционный предмет проигравшего. После завершённой дуэли с вероятностью 0,1% один из бойцов впадает в «Берсерк» и пытается дополнительно оторвать хуй другому.

`/me` показывает очки, победы, поражения, кражи, титулы, экипировку, инвентарь и питомца. `/inspect` позволяет осмотреть другого зарегистрированного игрока, `/duel_top` выводит десятку по победам.

Командой `/name Имя` можно один раз назвать гнома в конкретном чате. Имя ограничено 40 символами и затем не меняется. В сообщениях оно выводится рядом с Telegram-именем игрока.

`/dickpukku` после подтверждения удаляет гномьи данные игрока во всех чатах и блокирует дальнейшие игровые действия. Повторная регистрация обычными игровыми командами после этого недоступна.

## Предметы и экипировка

Каждая коллекционная вещь хранится отдельным экземпляром, поэтому одинаковых предметов может быть несколько. Нож и промасленная жилетка служат постоянными базовыми предметами для отображения и не входят в пул коллекционного лута.

Новые предметы собираются генератором из `data/loot/`: качество, одно или два определения, основа и источник в родительном падеже. Выбор учитывает веса в каталогах. Формы качества и определений согласуются с родом или множественным числом основы. Имя, тип и грамматическая форма сохраняются в БД, идентификатор получается транслитерацией имени. `loot/grammar.py` подставляет поддерживаемые падежные формы оружия и брони в боевые сообщения. Старый каталог `data/duel_items.json` используется для ранее существовавших предметов.

Лут появляется в чате с кнопкой «Подобрать». Его получает первый зарегистрированный участник, нажавший кнопку. Почасовая проверка создаёт такое событие с вероятностью 10%, если в чате нет другого неподобранного предмета. После дуэли у проигравшего с непустым инвентарём есть шанс 50% выронить коллекционную вещь в общий лут, если включены случайные события и место для общего лута свободно. После победы над боссом с вероятностью 50% один предмет получает случайный выживший.

Восемь слотов экипировки: головной убор (`head`), торс (`clothing`), пах (`groin`), оружие (`weapon`), верхняя одежда (`outerwear`), обувь (`footwear`) и два аксессуара (`accessory`, `accessory_2`). Полученный сгенерированный предмет автоматически занимает подходящий слот, заменяя надетую вещь; прежняя остаётся в инвентаре. Аксессуар сначала занимает первый слот, затем свободный второй, а при двух занятых заменяет первый.

Головной убор, одежда на торсе и защита паха поглощают одно успешное попадание в соответствующую зону в дуэли или бою с боссом. Поглотивший удар экземпляр уничтожается, слот освобождается. Верхняя одежда, обувь и аксессуары не дают такого поглощения. Оружие меняет боевые формулировки, отдельного бонуса к попаданию у него нет. В Mini App можно вручную надеть или снять подходящую вещь; менять экипировку участника активного боя нельзя.

После ручного подбора при включённых случайных событиях есть шанс 3% встретить хуегрыза: предмет остаётся у игрока, но тот может лишиться хуя. Потеря попадает в дневную хронику.

### Раскопки

`/dig` стоит 10 очков. У каждого гнома есть пять попыток на чат за московский календарный день. Каждая разрешённая попытка создаёт находку в общем луте: копавший не получает её автоматически. Пока в чате лежит неподобранный предмет, новая раскопка недоступна. При неудачной публикации находки предусмотрен возврат очков и попытки.

Команда и обычный ответ удаляются через 10 секунд. Сообщение с активной кнопкой находки остаётся до подбора.

### Хуекрабы и приманка

При почасовой проверке с вероятностью 5% появляется дикий хуекраб, если в чате есть зарегистрированный гном без питомца. Одновременно доступно одно такое событие, не более пяти появлений за день. Этот счётчик хранится в памяти процесса и использует календарную дату сервера.

Первый зарегистрированный игрок без хуекраба, нажавший кнопку приручения, расходует событие. Шанс приручения составляет 50%, повторной попытки у того же события нет. У гнома может быть один хуекраб в каждом чате.

Если предмет не подобрали за 20 секунд после публикации, хуекраб может забрать его владельцу. Фоновая проверка идёт раз в пять секунд. При нескольких владельцах выбирается случайный; питомцы при этом не теряются.

`/lure` уничтожает один случайный свободный коллекционный предмет из инвентаря. Надетые и базовые вещи не расходуются. После этого с вероятностью 10% бот пытается вызвать обычное событие дикого хуекраба. Сохраняются проверки включённого модуля, дневного лимита, активного события и наличия игроков без питомца. Потраченная вещь не возвращается, если хуекраб не появился.

## Боссы и случайные события

### Битва с боссом

Ежедневный бой запускается в 13:37 по Москве в чатах с включённым автоматическим боссом. `/boss_reg` записывает игрока на ближайший реально стартующий бой, автоматический или ручной. Под итогом боя есть кнопка записи на следующий. Во время 30-секундного набора можно присоединиться к текущему бою. `/boss` запускает его вручную и доступен администраторам бота.

Для боя выбирается уникальный босс из `texts/boss.yaml` либо генерируется новый из заданных там частей имени и диапазона здоровья. Необходимое число попаданий зависит от выбранного босса.

Живые участники выбирают атаку и защиту по тем же трём зонам. На каждую фазу даётся 10 секунд. Атака мимо блока босса засчитывает попадание; защита не в зоне его удара убивает участника, если надетый предмет не поглотил удар. Чат побеждает, когда набрано нужное число попаданий. Если живых не осталось, побеждает босс. Босс не отвечает на завершающее попадание.

В профиле учитываются победы над боссами. Результат боя сохраняется в SQLite и доступен в Mini App. Предварительная запись и выбранный следующий босс также сохраняются в БД, а текущий бой хранится в памяти процесса.

### Гиперборейский хуй, Король Артур и мох

Почасовая проверка с шансом 5% создаёт гиперборейское событие или событие Короля Артура. Для этой пары действует общий лимит: пять появлений за день на чат и одно активное событие. Счётчик и активное событие хранятся в памяти, дата берётся с сервера. Оба события предлагают выбор «Один хуй тебе или два другому?»:

- «Один мне» возвращает потерянный хуй. Если он уже есть, гном теряет его и все очки.
- «Два другому» выбирает случайного зарегистрированного гнома в чате, включая нажавшего. У выбранного без хуя обнуляются очки, хуй остаётся потерянным. Если хуй есть, состояние не меняется.

Тем же заданием отдельно проверяется событие мха с шансом 5%, не более одного появления на дату сервера в чате. Первый участник выбирает: «умный» устанавливает 100 очков, «мудрый» возвращает потерянный хуй.

### Личная хроника и месячная сводка

`/recap` показывает личные события текущего московского дня, от 00:00 до следующей полуночи. Дуэли сгруппированы по соперникам: кто кого вызывал, сколько побед и поражений. Отдельно показаны кражи и потери хуя, включая гиперборейское событие и Короля Артура, найденные, полученные, упущенные и потерянные вещи, приручение и добыча хуекраба. Потраченный на `/lure` предмет тоже попадает в хронику.

`/summary` выводит показатели чата за текущий московский месяц: обычные кражи хуя в дуэлях, проведённые дуэли и убитых боссов. Первого числа в 10:00 по Москве бот отправляет сводку за предыдущий месяц. Старые показатели сохраняются.

## Остальные возможности бота

В 10:00 по Москве бот выбирает «Пидора дня». `/top` показывает десятку по числу выборов. Команда `/setbday ДД.ММ` задаёт собственный день рождения; год тоже допустим. Чужую дату менять нельзя, повторная смена своей доступна через 365 суток.

`/gnomed`, отправленная ответом на сообщение, отвечает на него случайной гномьей фразой. Бот также реагирует на некоторые тексты, пересылки и дни рождения.

`/ball` активирует «Элитный мячик знание»: следующее обычное текстовое сообщение того же пользователя в том же чате становится вопросом. Команда удаляется через 10 секунд. Ответ «Увлажните шар гнома усерднее» выпадает с вероятностью 5%, «Да», «Нет» и «Возможно» с вероятностью 95/3% каждый.

В inline-режиме для непустого текста доступны результаты «Погода» и «Элитный мячик знание». Например, введите `@имя_бота Москва` и выберите погоду. Для мячика после отправки карточки её автор нажимает «Получить ответ». Это отдельный способ использования, он не расходует мячик, активированный через `/ball`. Команды `/weather` нет.

Механика `past_pizda` сохраняет подходящие сообщения с «да» и позднее отвечает на одно из них «Пизда». Интервал между запусками выбирается от двух до семи дней. Пул и расписание сохраняются в SQLite.

Администратор через `/modules` включает и отключает случайные события дуэлей, автоматического босса, месячную сводку, отложенные ответы, реакции чата и поздравления. По умолчанию все модули включены. Эти настройки управляют источниками автоматической активности, а не отключают все ручные команды.

## Mini App и HTTP API

Для входа нужен зарегистрированный гном и команда `/app` в игровом групповом чате. Кнопка содержит персональную ссылку на Main Mini App бота. В приложении пять вкладок:

- **Главная**: профиль гнома, статистика, питомец, инвентарь и управление экипировкой.
- **Соперники**: игроки чата, их профили и запуск дуэли.
- **Дуэль**: личная хроника за сегодня, текущая дуэль, выбор хода и последний личный результат. Другие игроки могут наблюдать текущий бой.
- **Зал славы**: десятка игроков по победам.
- **Боссы**: текущий бой, присоединение во время набора, атака и защита, результат завершённого боя.

Дуэль в Telegram и Mini App использует одну сохранённую сессию. Выбор хода через любой из интерфейсов изменяет тот же бой; сервер проверяет участника, фазу, номер хода и срок действия.

### Авторизация

`POST /api/v1/session` принимает JSON с `init_data` и `launch_token`. Подпись Telegram `initData` проверяется через `BOT_TOKEN`, допустимый возраст составляет пять минут. Одноразовый launch token действует 120 секунд и связан с пользователем и чатом команды `/app`. Его обмен выдаёт `session_token` на один час. Чат и пользователь последующих запросов определяются серверной сессией; переданный клиентом `chat_id` не задаёт контекст.

Остальные игровые маршруты требуют заголовок `Authorization: Bearer <session_token>`. Истёкшую сессию нужно открыть заново через `/app`. Токены хранятся в SQLite в виде SHA-256-хешей.

### Маршруты

| Метод и путь | Назначение |
|---|---|
| `POST /api/v1/session` | Обмен launch token и Telegram initData на сессию |
| `GET /api/v1/me` | Собственный профиль, инвентарь и экипировка |
| `GET /api/v1/recap` | Личная хроника текущего московского дня |
| `GET /api/v1/players/{target_user_id}` | Профиль игрока этого чата |
| `GET /api/v1/equipment/{slot}` | Доступные экземпляры для слота |
| `POST /api/v1/equipment/equip` | Надеть предмет: `slot`, `inventory_id` |
| `POST /api/v1/equipment/unequip` | Снять предмет: `slot` |
| `GET /api/v1/duel/opponents` | Игроки чата и доступность вызова |
| `GET /api/v1/duel/hall-of-fame` | Топ-10 по победам |
| `POST /api/v1/duel/start` | Начать бой: `opponent_user_id` |
| `GET /api/v1/duel/active` | Текущий бой и последний личный результат |
| `POST /api/v1/duel/move` | Ход: `duel_id`, `turn_id`, `zone` |
| `GET /api/v1/boss` | Текущий босс и сохранённый результат |
| `POST /api/v1/boss/join` | Присоединиться: `battle_id`, `round` |
| `POST /api/v1/boss/action` | Ход: `battle_id`, `round`, `phase`, `action_id` |

Для дуэльного `zone` используются `head`, `body`, `dick`. В запросах босса нужно передавать идентификаторы текущего состояния из ответа API, `phase` принимает `attack` или `block`.

FastAPI отдаёт клиент по `/` и `/app`, статику по `/static/`, изображения гномов по `/media/gnome` и `/media/gnome/{variant}`. `/healthz` проверяет доступность HTTP-сервера. Telegram WebApp SDK находится в `miniapp_static/vendor/` и загружается с того же origin.

## Структура и хранение данных

`bot.py` регистрирует команды, callback-обработчики и задания. Telegram polling, JobQueue и Uvicorn работают в одном процессе и одном цикле событий. Запуск рассчитан на один экземпляр бота с одним HTTP worker.

| Путь | Содержимое |
|---|---|
| `config.py` | Загрузка окружения, игровые константы и JSON-контент |
| `handlers/` | Команды, игровые механики, сервисы дуэлей и боссов, сообщения |
| `database.py` | SQLite-схема, миграции и операции с игровыми данными |
| `duel_session_repository.py`, `duel_outbox_repository.py` | Сохранённые дуэли и очередь публикаций в Telegram |
| `miniapp_api.py`, `miniapp_auth.py`, `miniapp_sessions.py` | HTTP API, проверка initData и сессии |
| `miniapp_static/`, `gnome_avatars.py` | Клиент Mini App и изображения профилей |
| `loot/`, `data/loot/` | Генерация предметов, грамматика и каталоги |
| `data/` | JSON-каталоги предметов, фраз и медиа |
| `texts/`, `text_resources.py` | YAML-тексты и их загрузчик |
| `tests/` | Pytest и JavaScript-проверки интерфейса |
| `TEXT_MIGRATION_AUDIT.md` | Аудит переноса пользовательских строк в YAML |

`init_db()` вызывается при старте, создаёт таблицы и применяет встроенные миграции. Основной файл БД: `bot_database.db` в корне проекта; запускать `bot.py` нужно из этого каталога.

В `users` хранятся участники основной игры и дни рождения, в `duel_users` профили гномов по чатам. `duel_inventory` содержит экземпляры вещей, `generated_item_names` их сгенерированные имена и метаданные, `duel_equipment` связывает экземпляры со слотами. Для лута и питомцев служат `duel_item_events`, `huecrab_owners`, `huecrab_events`; для хроники `game_events`, для раскопок `duel_dig_daily`, для месячных итогов `monthly_chat_stats`.

Таблицы `duel_sessions` и `duel_outbox` сохраняют ход обычной дуэли и публикации. При старте бот восстанавливает незавершённые дуэли, а фоновый worker обрабатывает очередь и таймауты. Итоги боссов сохраняются в `boss_battle_results`; очередь участников и следующий босс в `boss_next_registrations` и `boss_next_battles`, которые создаёт `handlers/boss_registration.py`. Настройки чатов, отключённые модули, Mini App, мячик и отложенные ответы также хранятся в БД. Текущие бои с боссами и часть событий в памяти после перезапуска не восстанавливаются.

### Тексты YAML

`text_resources.py` загружает UTF-8-файлы `texts/*.yaml` и кэширует их в процессе. Ключ начинается с имени файла: `get_text("recap.title")`. `get_text()` форматирует именованные плейсхолдеры, `get_text_list()` возвращает список, `get_text_mapping()` словарь строк. При изменении текста нужно сохранять имена плейсхолдеров и Telegram HTML-разметку. Для применения изменений работающий процесс перезапускают. Часть строк Mini App и контента остаётся в Python, JavaScript и JSON.

## Локальный запуск

В Docker используется Python 3.13. Файлы зависимостей рассчитаны на CPython 3.10 и 3.13; для одинакового окружения с контейнером используйте 3.13. SQLite входит в Python. Для JavaScript-проверок нужен Node.js.

PowerShell:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Если активация запрещена политикой PowerShell, разрешите её для текущего процесса через `Set-ExecutionPolicy -Scope Process Bypass` и повторите активацию.

Linux и macOS:

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
```

Для работы без тестовых инструментов достаточно `requirements.txt`. В нём закреплены FastAPI, python-telegram-bot с JobQueue, Uvicorn, python-dotenv, pytz, PyYAML, requests и их зависимости. `requirements-dev.txt` добавляет pytest и pytest-asyncio.

### Окружение

Заполните `.env` и не добавляйте его в Git. Шаблон `.env.example` содержит `BOT_TOKEN` и `ADMIN_IDS`; HTTP-настройки при необходимости добавляются вручную.

| Переменная | Назначение и значение по умолчанию |
|---|---|
| `BOT_TOKEN` | Обязательный токен Telegram-бота, также используется для проверки initData |
| `ADMIN_IDS` | Telegram ID администраторов бота через запятую |
| `ADMIN_ID` | Старое имя настройки, читается только при отсутствии `ADMIN_IDS` |
| `MINIAPP_HTTP_HOST` | Адрес HTTP-сервера, по умолчанию `127.0.0.1` |
| `MINIAPP_HTTP_PORT` | Порт HTTP-сервера, по умолчанию `8000` |
| `MINIAPP_ORIGIN` | Необязательный единственный разрешённый HTTPS origin для CORS, без пути и завершающего `/` |

Запуск из корня репозитория:

```bash
python bot.py
```

По умолчанию проверка доступности находится по адресу `http://127.0.0.1:8000/healthz`. Для Mini App настройте у бота в Telegram Main Mini App на публичный HTTPS-адрес с маршрутом `/app`. Приложение открывается через `/app` из группы. Для inline-погоды и мячика у бота должен быть включён inline-режим. Для автоудаления команд боту нужны права удаления сообщений в группе.

### Начальный пул отложенных ответов

Для загрузки старых сообщений можно положить Telegram JSON-экспорт в `data/result.json` и выполнить:

```bash
python -m handlers.past_pizda --from-export
```

`python -m handlers.past_pizda --export-seed` сохраняет пул в `data/pizda_candidates_seed.json`, а `python -m handlers.past_pizda` импортирует этот seed. Эти файлы нужны только для ручного переноса истории; обычный запуск использует БД.

## Развёртывание на VPS

Рабочая схема использует обычный Docker. Репозиторий находится в `/opt/da-pizda-bot`, ветка `miniapp`, образ `da-pizda-bot:miniapp-next`, контейнер `da-pizda-bot`.

`Dockerfile` основан на `python:3.13-slim-bookworm`, устанавливает `requirements.txt`, копирует проект в `/app` и запускает `python bot.py`. `.dockerignore` исключает `.env`, локальные SQLite-файлы, резервные копии, окружения и тесты.

В серверном `.env` должны быть `MINIAPP_HTTP_HOST=0.0.0.0` и `MINIAPP_HTTP_PORT=8000`. Dockerfile сам их не задаёт: без смены адреса привязки публикация порта не даст доступа к серверу внутри контейнера. Публичный HTTPS reverse proxy должен направлять запросы на `127.0.0.1:8000` хоста. `MINIAPP_ORIGIN` задаёт CORS, но не настраивает HTTPS или адрес запуска приложения.

Файл `/opt/da-pizda-bot/bot_database.db` должен существовать на хосте до `docker run`. При первом развёртывании создайте пустой файл через `touch bot_database.db`; существующую игровую БД сохраните. Bind mount ниже подключает именно этот файл, поэтому удаление контейнера не удаляет игровые данные.

Обновление существующего контейнера:

```bash
cd /opt/da-pizda-bot

git fetch origin
git pull --ff-only origin miniapp

docker build -t da-pizda-bot:miniapp-next .

docker stop da-pizda-bot
docker rm da-pizda-bot

docker run -d \
  --name da-pizda-bot \
  --restart always \
  --env-file .env \
  -p 127.0.0.1:8000:8000 \
  -v "$(pwd)/bot_database.db:/app/bot_database.db" \
  da-pizda-bot:miniapp-next
```

При первом запуске шаги `docker stop` и `docker rm` пропускаются. После обновления проверьте `docker logs --tail 100 da-pizda-bot` и `curl -f http://127.0.0.1:8000/healthz`, затем вход в Mini App из Telegram.

### Резервная копия и откат

Перед удалением остановленного контейнера сохраните БД и предыдущий образ. Копировать файл базы следует после `docker stop`:

```bash
mkdir -p backups
cp bot_database.db "backups/bot_database-$(date +%Y%m%d-%H%M%S).db"
```

При обновлении образа под тем же тегом заранее присвойте текущему образу отдельный тег, чтобы сохранить его для отката. Прежний образ можно запустить с той же БД, если схема совместима. При несовместимой миграции восстановите копию, сделанную до обновления, при остановленном контейнере. При этом игровые изменения после создания копии будут потеряны.

## Тесты и проверки

После установки `requirements-dev.txt`:

```bash
python -m pytest -q --tb=short
node --check miniapp_static/app.js
git diff --check
```

`pytest.ini` задаёт каталог `tests`, автоматический режим asyncio и вывод краткой информации о результатах. Тесты игровых данных используют временные SQLite-базы. JavaScript harness-проверки вызываются из pytest при наличии Node.js, без него соответствующие тесты пропускаются.

При изменении только Markdown достаточно проверить команды, пути и `git diff --check`; полный игровой набор тестов для этого не нужен.
